# 表格短信助手 · 无间隔极速自动版

一个**纯前端、单文件**的移动端网页工具：上传 Excel 通讯录 → 勾选号码 → 一键连续唤起系统短信编辑页 → 导出唤起记录对账。

> 单文件 `index.html`，样式全部内嵌，依赖库（SheetJS）走 CDN 在线加载，双击本地文件也能打开。

---

## 一、功能清单

| # | 功能 | 说明 |
|---|------|------|
| 1 | 上传 Excel | 支持 `.xlsx / .xls / .csv`，首行表头**必须包含【手机号】列**，其余自定义字段（姓名、公司、金额……）自动识别 |
| 2 | 模板变量替换 | 短信模板中用 `{列名}` 引用表格内容，例如 `尊敬的{姓名}，您好！` |
| 3 | 勾选待发送号码 | 逐行勾选，或「全选 / 取消全选」，表头复选框也可一键全选 |
| 4 | 无间隔极速模式 | 拉起系统短信编辑页（`sms:` 协议），**唤起即刻记录日志**，0 等待直接跳下一条号码 |
| 5 | 实时进度展示 | 显示当前处理号码、第几条 / 共几条 |
| 6 | 停止任务 | 随时终止批量任务，已唤起的记录保留 |
| 7 | 导出发送记录 | 导出 `.xlsx`，字段：**手机号 / 短信内容 / 唤起时间** |
| 8 | 红色风险提示 | 页面显著位置提示「网页无法感知短信是否真实发送」 |
| 9 | 发完短信自动回浏览器 | 安卓可选开关：用隐藏 iframe 唤起短信，主页面保持活跃，关闭短信后自动跳回本页面（iOS 因系统限制不支持） |

移动端适配，安卓手机浏览器打开体验最佳。

## 二、使用说明

1. 手机浏览器打开 `index.html`（或部署到静态服务器后访问）。
2. **上传表格**：点击「上传Excel表格」，选择文件。
   - 表格第一行是表头，其中必须有 `手机号` 这一列；
   - 后面的列名随意，模板里用 `{列名}` 取用；
   - 手机号为空的行会被自动过滤，不上屏。
3. **写模板**：在「短信模板」里编写内容，用 `{姓名}`、`{公司}` 等占位，例如：
   ```
   尊敬的{姓名}，您好！您在本公司登记的号码是{手机号}，详情请联系客服。
   ```
4. **勾选号码**：在表格里勾选要发送的号码（可点「全选」）。
5. **开始**：点击「开始无间隔批量唤起」。页面会立刻跳转到系统短信应用，短信正文已按模板填好。
6. **返回浏览器**：在短信页处理完（发不发都行），切回浏览器，会自动跳入下一条号码。
   - 想中途停止，点击「停止任务」。
7. **导出对账**：全部结束后点击「导出发送记录」，得到 `短信发送记录_时间戳.xlsx`。

### 关于「续跑」的工作方式

受浏览器安全限制，网页无法在后台自动连续打开短信 App，因此工具采用以下策略保证任务不中断：

- 唤起前先把本条记录写入日志，并把任务状态存进 `localStorage`；
- 用户从短信 App **切回浏览器**时（`visibilitychange` 事件）立即跳转下一条号码，实现「0 等待」；
- 即使浏览器把页面回收重载，打开后也会从 `localStorage` 恢复队列与进度继续执行；
- 若短信 App 未能拉起（页面仍在前台），约 1.2 秒后自动跳过，避免任务卡死。

> 注意：恢复机制依赖 `localStorage`。若在运行中途手动刷新页面或更换设备，请重新上传表格。

### 苹果手机（iOS）使用说明

iOS 与 Android 的机制不同，程序会**自动识别**并切换模式：

| | Android / 通用浏览器 | iPhone / iPad（iOS） |
|---|---|---|
| sms: 协议格式 | `sms:号码?body=内容`（`?`） | `sms:号码&body=内容`（`&`） |
| 唤起方式 | 自动连续跳转 | **每条点击一次**绿色按钮 |
| 记录时机 | 跳转瞬间记录 | 确认短信页已打开后记录（更准） |

在 iPhone 上操作：

1. 上传表格、写模板、勾选号码，步骤与安卓一致；
2. 点「开始批量任务（苹果逐条模式）」；
3. 点一次绿色按钮「点击唤起短信（第 X/Y 条）」→ 系统「信息」App 打开，正文已填好；
4. 处理完切回浏览器，**下一条号码立刻出现**，再点一次按钮即可，如此往复；
5. 想停下直接点「停止任务」，已记录的日志保留。

为什么苹果手机不能像安卓一样全自动？因为 iOS 出于安全限制，**只有用户的手指点击**才被允许唤起「信息」/电话等系统 App，用定时器或页面切回自动触发的跳转会被 Safari 静默拦截，甚至弹出「无法打开页面」。所以苹果手机上每条需要 1 次点击，这是系统层面的限制，无法绕过。

> 使用微信 / QQ / 钉钉等 App 内置浏览器打开时，页面顶部会出现橙色警告：这些内置浏览器会屏蔽 `sms:` 协议，请点右上角「…」→「在 Safari 中打开」。

## 三、风险警告（务必阅读）

- 本工具**只负责唤起短信编辑页并把内容填好**，**不会、也无法自动点击「发送」**。
- 网页**无法感知短信是否真实发送成功**：只要短信编辑页被唤起，就立刻计入日志，**无论用户是否最终发送**。
- 因此导出的记录是「**唤起日志**」，不是「实际发送记录」，请以运营商短信详单为准，本日志仅适合**事后人工对账**。
- 批量唤起属于高频操作，部分手机（尤其开启短信拦截 / 系统限制后台）可能限制跳转频率；使用前请小批量（3~5 条）验证。
- 请仅向**已获得授权、已告知**的联系人发送短信；擅自批量群发可能违反《个人信息保护法》《反电信网络诈骗法》及运营商规定，由此产生的一切后果由使用者承担。

## 五、已修复的原代码问题

1. **CDN 地址带反引号**：`src="\`https://...\`"` 会导致库加载失败，已改为正常 URL，并增加 unpkg 备用 CDN 兜底。
2. **批量唤起不会真正循环**：原逻辑只 `loadItem()` 一次就跳转，页面失去状态后无法继续下一条。已改为「状态持久化 + 返回续跑 + 页面前台兜底」三步机制。
3. **【手机号】列校验缺失**：原代码在表头没有「手机号」时，`indexOf` 返回 `-1`，会把全部行错误过滤为 0 条且无提示。现已显式校验并给出红字提示。
4. **模板替换存在注入风险**：原来直接 `replace(reg, row[i])`，当单元格内容含 `$&`、`$1` 等字符时会被错误解析。现改为函数式替换。
5. **列名含正则特殊字符**：`{姓名(1)}` 这类列名会构造出非法正则，已对列名做转义。
6. **停止任务误报完成**：原 `loadItem()` 在用户点「停止」时也会弹出「全部任务执行完毕」。现停止与完成分支分离。
7. **表头全选复选框无效**：原 `mainCheck` 没有绑定任何事件，现已实现一键全选/取消。
8. **原始手机号丢失**：Excel 中手机号被格式化为数字 / 科学计数法时（如 `1.38E+10`）会出错，请把该列设为**文本格式**再上传，导出前请核验。
9. **无文件解析异常处理**：损坏文件、非表格文件会静默失败，现已加 `try/catch` 与错误提示。
10. **日志跨会话丢失**：现发送记录随任务一起持久化，中途返回/重载不会丢记录。

### 苹果手机修复（本次）

11. **iOS `sms:` 协议分隔符用错**：原代码统一用 `sms:号码?body=内容`（Android/RFC 5724 格式）。iOS 的「信息」App 只认 `&` 分隔符，用 `?` 时 Safari 会直接弹出「无法打开页面」，任务当场中断。现已按平台自动切换（iOS 用 `&`，其余用 `?`）。
12. **iOS 不允许非手势触发唤起系统 App**：原代码用 `window.location.href` 在定时器 / `visibilitychange` 回调里跳转，iOS 会静默拦截或报错，导致「点了开始没反应」。现苹果手机改为**点击逐条模式**——显示号码 → 用户点绿色按钮 → 唤起，返回后自动出现下一条。
13. **iOS 唤起改用 `<a>` 元素点击**：比直接改 `location.href` 更容易被 Safari 放行，进一步减少「无法打开页面」弹窗。
14. **微信 / QQ / 钉钉等内置浏览器屏蔽 `sms:`**：新增顶部橙色警告，引导用户改用 Safari 打开。
15. **iOS 记录更准确**：只有确认短信页真的被打开，才写入日志并前进；若点按后仍停留在本页（说明被拦截），会提示重试而不是误记一条。
16. **不带 BOM 的 CSV 中文表头乱码**：原代码一律用 `readAsArrayBuffer` 交给 SheetJS，SheetJS 对无 BOM 的 CSV 按 latin1 解码，中文表头变成乱码，随后误报「表头缺少【手机号】列」。现对 `.csv/.txt/.tsv` 先按 UTF-8 解码，若出现替换字符（说明实为 GBK 编码）自动改用 GBK 解码重试；`.xlsx/.xls` 仍走原有二进制路径。
17. **发完短信自动回浏览器**：原代码用 `window.location.href = sms:` 跳转，主页面被导航、浏览器退到后台，关闭短信后不一定能回到浏览器。现新增「发完短信自动回到浏览器」开关（默认开启）：用**隐藏 iframe** 加载 `sms:` URL，主页面不被导航、保持活跃；短信 App 作为新任务打开，关闭后系统自动回到本页面。并尝试 `window.focus()` 拉回浏览器；若 iframe 未成功拉起短信（页面仍可见），自动兜底用 `window.location.href`。该功能仅安卓可用，iOS 因系统安全限制仍需逐条点击。

## 七、部署到 htmlpreview.github.io 在线预览

`htmlpreview.github.io` **自己不存储文件**，它只是把「GitHub 仓库里的 HTML 文件」渲染出来。因此只要把本项目推到任意一个 GitHub 仓库，就能得到在线可访问的地址。

### 步骤

1. 登录 GitHub，点右上角 `+` → **New repository**，仓库名例如 `sms-helper`，选择 **Public（公开）**，不要勾选 Add README。
2. 在本项目目录执行（把 `你的用户名/仓库名` 换成实际值）：

```bash
cd /workspace
git init -b main
git add index.html README.md
git commit -m "feat: 表格短信助手（安卓全自动 + 苹果逐条唤起）"
git remote add origin https://github.com/你的用户名/仓库名.git
git push -u origin main
```

3. 推送成功后，用下面任一地址在手机上打开即可（把用户名/仓库名替换掉）：

```
https://htmlpreview.github.io/?https://raw.githubusercontent.com/你的用户名/仓库名/main/index.html
```

或使用 GitHub 的 blob 链接（htmlpreview 会自动转成 raw）：

```
https://htmlpreview.github.io/?https://github.com/你的用户名/仓库名/blob/main/index.html
```

例如仓库是 `zhangsan/sms-helper`，则在线地址是：

```
https://htmlpreview.github.io/?https://raw.githubusercontent.com/zhangsan/sms-helper/main/index.html
```

### 注意事项

- **仓库必须是公开的**：htmlpreview 走 `raw.githubusercontent.com` 拉取原始文件，私有仓库的 raw 链接需要鉴权，htmlpreview 拿不到。
- **国内网络问题**：`htmlpreview.github.io` 与 `raw.githubusercontent.com` 在中国大陆经常被墙或极慢，手机打开可能超时白屏。若打不开，建议改用国内可访问的静态托管（Gitee Pages、腾讯云 COS、又拍云、Vercel 自定义域名等），本工具是纯静态单文件，丢到任何静态托管都能跑。
- **运行机制**：htmlpreview 会把你的 HTML 源码注入到它自己的顶层文档里执行，所以 `localStorage`（写日志/恢复任务）与 `sms:` 顶层跳转都能正常工作。
- **微信/QQ 打开无效**：内置浏览器屏蔽 `sms:` 协议，页面顶部会弹橙色警告，请改用系统自带浏览器 / Safari 打开。
- 首次加载需要从 `cdn.jsdelivr.net` 取表格库，若被墙会自动回退到 `unpkg.com`。
